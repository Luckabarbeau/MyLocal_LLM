# PATCH 0089T — Historical block optimization acceptance audit

## Decision

Retain the Triton deterministic historical block forward as an explicit
production opt-in:

```bash
export MINI_LLM_TRITON_HISTORICAL_BLOCK_FORWARD=1
export MINI_LLM_TRITON_HISTORICAL_BLOCK_PREWARM=1
```

Do not enable it silently for other precision modes or configurations. The
complete-model native parity thresholds still fail, but the additional audit
found no indexing, masking, crop, layout, or mathematical-equation defect in
the production BF16/FP32 path. The discrepancy is consistent with small local
floating-point/reduction differences crossing BF16 rounding boundaries and
amplifying through the model.

The user reports an observed production throughput increase from approximately
25k supervised tokens/s to slightly above 26k supervised tokens/s. This is a
useful operational result but is recorded as user-observed rather than as a
controlled benchmark artifact.

## Mathematical contract

For each deterministic block slot, both paths compute:

```text
I = exact scheduled 32-of-period source indices
S = (FP32(Q) @ FP32(K[I])^T) / sqrt(64)
P = masked_softmax(S)
O = P @ FP32(V[I])
```

The Triton path differs only in floating implementation:

- direct implicit source indexing instead of gathered K/V;
- tiled `tf32x3` dot products;
- `exp2(x * log2(e))` instead of natural exponential;
- two-pass tiled maximum/sum reductions;
- different summation and accumulation order.

It retains FP32 accumulators and returns FP32 before the existing gate and BF16
context-storage boundary.

## Independent source review

An independent review found no defect in the reachable production domain:

- absolute-to-cropped source coordinates are correct;
- partial/tail handling is consistent for aligned production histories;
- non-contiguous Q token/batch strides are honored;
- all-invalid rows return exact finite zero;
- per-sample inactive history preserves the original current-attention head;
- scale and softmax equations are mathematically equivalent;
- forward retains the exact reference selection for backward;
- no K/V or query gradient path is missing or shifted.

Two API restrictions remain:

1. The optimized pointer adapter supports BF16/FP32 Q, FP32 K/V, and bool masks.
   The current production BF16 path satisfies this contract; arbitrary FP16 or
   FP64 callers do not.
2. Physical source crops must be 32-token aligned. `HistoricalReadMemory.open`
   guarantees this; per-sample unaligned validity remains represented by the
   boolean mask.

## Backward consistency

Backward is deliberately unchanged. It uses the exact cached
`source_indices`, reconstructs probabilities through the CuPy FP32 reference,
and applies the established Q/K/V and gate gradient equations.

Consequently, it is the backward of the reference mathematical attention, not
the exact discrete derivative of Triton's tiled `tf32x3`/`exp2` arithmetic. The
local forward discrepancy is approximately `1e-6`, so this is best described as
an approximate-forward/reference-mathematics-backward pairing. This pattern is
numerically common for recomputed fused attention, but it must be acknowledged.

The complete-model discrepancy is still real:

```text
Body-output relative L2:       5.5648e-3
Body-output cosine:            0.9998955
Global gradient relative L2:   1.3625e-2
Worst small-tensor cosine:     0.9923513
Loss absolute difference:      6.6996e-5
```

The direct audits show that these values do not originate from incorrect source
selection or a wrong local attention equation. They arise after repeated small
read differences cross BF16 rounding boundaries and alter downstream BF16
projection inputs.

## Acceptance boundary

Keeping the optimization is defensible as an explicit training configuration
because:

- all direct production calls implement the intended operation to about `1e-6`
  relative L2;
- source selection and causality are exact;
- invalid-history behavior is exact;
- outputs remain finite;
- the user observes a material end-to-end throughput improvement;
- no architectural semantics, compact-history representation, or checkpoint
  format changes.

It should not be described as native bitwise/numerical parity. Recommended
operational safeguards are:

1. Preserve the flag in training metadata and checkpoints/logs.
2. Do not switch the flag silently within one training run.
3. Compare validation loss at fixed checkpoints over a short controlled
   trajectory before making it the general default.
4. Monitor gradient norms, non-finite counts, and historical gate values.
5. Keep the CuPy reference path available for diagnosis and reproducibility.
