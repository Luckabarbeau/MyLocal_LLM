# Patch0206 — Separate bounded-table PLE reference

## Scope and provenance

existing verified components. Before implementation, the following local sources
were inspected at their actual revisions:

- llama.cpp `171e8846b4af9766c354064cb776cb34a50f053f`,

The runtime has no dependency on a source checkout, expert residency, or torch.

## API and ownership

```python
ple = Qwen4ExpPLE.from_store(
    store,
    key=key_projection, value=value_projection,
    gamma_key=gamma_k, gamma_query=gamma_q, gamma_conv=gamma_conv,
    conv=conv_weights,
)
state = ple.fresh_state()
updated_streams, state = ple.step(token_id, streams, state)
```

The caller supplies already-decoded FP32 backend arrays: key `[10240,2560]`,
value `[2560,2560]`, three gammas `[4,2560]`, convolution `[10240,4]`.
Projections can instead be pure exact linear callables accepting `[2560]` and
returning `[10240]`/`[2560]` FP32 arrays on the selected `xp` backend. Callable
shape/dtype is checked on execution; their numerical meaning is the caller's
responsibility. Dense arrays are copied at construction. No weights are decoded
by `from_store`. Converted gamma is used directly, with **no additional +1**.

`from_store` validates metadata geometry, unsigned integer hash constants, each
head's range and IQ4_NL table shape `[table_rows,160]`. It uses the exact metadata
multipliers, offsets, moduli and **PLE EOS**, not tokenizer EOS. The default
epsilon is `qwen4exp.attention.layer_norm_rms_epsilon`; it can be supplied
explicitly. There is no hardcoded table row count or hash multiplier.

`step` accepts exactly `[4,2560]`, one token and one sequence. Batch axes,
shared-token sequences and multimodal embedding batches are explicitly
unsupported; the caller must supply actual integer token IDs. Loop over tokens
for sequential prefill. Four streams are channels, not token history, and are
never mixed across time by the projection/gating logic.

`PLEState` contains two oldest-first predecessor tokens and nine oldest-first
normalized convolution rows `[9,4,2560]`. Its representation is canonical Python,
not Strata's row-fastest physical storage. `step` returns a new state and does
not mutate either the original streams or state. The dataclass is frozen but
its backend array is caller-owned: do not modify it during asynchronous use.
No sequence state is held on the module. Separate requests must retain separate
states. `fresh_state()` is the explicit reset (missing tokens `-1`, zero conv
history); module weights/store may be shared between requests. Keep the store
open throughout execution. Ordinary backend stream ordering remains the caller's
responsibility; concurrent mutation of state/weights is not supported.

## Exact dependency chain

1. Read current token and two predecessors. Walking newest predecessor to oldest,
   missing/negative or PLE-EOS predecessor cuts that position and all older
   positions to PLE EOS. **Current EOS does not cut its own preceding context.**
2. Multiply each token and metadata multiplier modulo `2**64`, then XOR for
   bigram/trigram. Python integer masking avoids warning-producing overflow.
   Emit eight bigram and eight trigram head rows using each head's modulus and
   offset, preserving head order.
3. Read/decode sixteen single rows via `MultiShardTensorStore.rows` and
   `PackedGGUFWeight.dequantize_rows_reference(tile_rows=1)`. Flatten
   `[16,160]` to `[2560]`. Only those rows are copied to GPU. Never decode,
   materialize, cache, or upload the full table. CPU decoded output is 10 KiB
   per token, with one-row decoder scratch; the original table remains mapped.
4. `k = RMSNorm_gamma_k(reshape(W_k @ emb,[4,D]))`,
   `q = RMSNorm_gamma_q(X)`, `v = W_v @ emb`.
5. `s = sum_D(k*q)/sqrt(D)`;
   `gate = sigmoid(sign(s)*sqrt(max(abs(s),1e-6)))` (zero score gives exactly .5).
6. `u = gate[:,None]*v`, `z = RMSNorm_gamma_conv(u)`.
7. Per-channel convolution uses weights `[4D,4]` at
   `z[t-9], z[t-6], z[t-3], z[t]`, in that order. Initial history is zero.
8. Return `X + (u + SiLU(conv))`; append **normalized z once**, advancing history
   by exactly one row. No gated-but-unnormalized history and no duplicate advance.

All floating execution is FP32 `xp` (NumPy or selected CuPy). Stable sigmoid
avoids exponent overflow at saturation. As elsewhere in the FP32 reference,
extreme inputs that overflow FP32 products/reductions are not repaired or
silently approximated. EOS affects future hash windows but **does not clear the
convolution history**. Resetting a sequence is a separate explicit operation.

## Validation and limits

Focused command:

```sh
.venv/bin/python -m pytest -q tests/test_0206_qwen4exp_ple.py
```

Tests include:

- Real sparse GGUF IQ4_NL table with 16,000,048 rows (1.44 GB logical size,
  only selected pages written); independent nibble/codebook row oracle.
- Instrumented single-row reads/decodes and forbidden whole-table accessors.
- Independent unsigned hash oracle with overflow, sequence start, repeated
  tokens, negative missing predecessors, current/prior EOS and distinct
  tokenizer EOS.
- Optional compilation/execution of original hash functions extracted from the
  pinned Strata source, revision-checked. This test skips if the checkout or C++
  compiler is unavailable; set `QWEN4EXP_STRATA_SOURCE` to relocate the checkout.
  This is a test-only optional source dependency, never a runtime requirement.
- Float64 projection/norm/gate/dilated-convolution/state oracle over fifteen
  positions, including zero/positive/negative gates and EOS. FP32 comparisons
  use explicit tolerances, not a bitwise full-model parity assertion.
- Reset/replay and interleaved request isolation; input/state nonmutation;
  shape/dtype/metadata/table/epsilon/projection validation.
- Optional actual CuPy subprocess rerunning portable tests when an installed
  CuPy and usable device are available; otherwise explicitly skipped.

These establish synthetic operator behavior only. Real checkpoint projection
outputs, layer integration, multimodal predecessor selection, complete logits,
throughput and numerical equivalence to an executed full llama/Strata model
remain unvalidated. CPU per-row decode and backend copy are deliberate bounded
correctness paths, not performance claims.
