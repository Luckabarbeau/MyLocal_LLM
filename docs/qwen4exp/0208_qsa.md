# Patch0208 — standalone FP32 TEXT QSA

## Scope and API

New implementation: `mini_llm/external/qwen4exp_attention.py`; tests:
`tests/test_0208_qwen4exp_attention.py`. No loader, decoder, training path,
checkpoint payload, existing module, or shared status document is changed.
Input is the already-normalized attention branch input, not residual streams.
Output is the projected gated attention branch, without a residual addition.

`QSAConfig(d_model=2560)` defaults to checkpoint attention geometry: 24 query
heads, 2 KV heads, head width 256, rotary prefix 64, indexer 4 query heads of
width 128 and one key head, compression 4, top-k 2048, base 1e7, sections
`(11,11,10,0)`. Epsilon defaults to 1e-6; pass the checkpoint epsilon explicitly
when integrating. `attention_scale=None` means `1/sqrt(head_dim)`; an explicit
positive scale supports the source graph's override. Dimensions are configurable
for synthetic tests; no GGUF metadata loader is implied.

Construct `Qwen4ExpAttention(config, query_gate=..., key=..., value=...,
output=..., index_query=..., index_key=..., gamma_q=..., gamma_k=...,
gamma_index_q=..., gamma_index_k=...)`. Dense weights are copied FP32 backend
arrays in **[output,input]** order. Alternatively each projection is a pure
callable `[input] -> [output]` returning a finite FP32 backend array. Gamma is
one shared vector per head width and is already converted: do not add one.

```python
state = attention.create_state(max_length=4096)
y = attention.step(hidden_vector, state, position=0)
ys = attention.forward(hidden_chunk, state, start_position=1)
y, diagnostic = attention.step(next_hidden, state,
                               position=state.length, diagnostics=True)
attention.reset(state)
```

One state represents one sequence and belongs to one attention instance. Only
zero-origin, contiguous, nonnegative **scalar** text positions are accepted;
`position == state.length`. Offsets, holes, arbitrary position arrays, multimodal
axes, multi-sequence batches, padding/custom masks, sliding windows and shared
prefix caches are rejected or outside this API. Start a new sequence with reset
or a fresh state. The caller must not mutate caches or share a state concurrently.
Sequential prefill is deliberately used, not a batched approximation.

Inspected local llama.cpp HEAD:
`171e8846b4af9766c354064cb776cb34a50f053f` at
`/home/lucka/softwares/local_llm_lab_north_v7/local_llm_lab/vendor/llama.cpp`.
Primary graph: `src/models/qwen4exp.cpp:542–858`; cache membership/bias:
`src/llama-memory-hybrid-idx.cpp:462–581`; CPU selection and rotation:
`ggml/src/ggml-cpu/ops.cpp`. Also inspected Strata
`include/strata/kernels/qsa.hpp`, especially the raw-key pooling, spare-key,
finite-tail and top-k contracts. Its revision provenance is recorded in
`reference_contract.md`; this patch does not independently certify the Strata
checkout or the checkpoint payload.

1. Project `[Q_head | gate_head]` per query head, not global Q/gate halves.
2. Independently RMS-normalize each Q and K head, then apply partial text
   IMRoPE. V is neither normalized nor rotated.
3. Independently project indexer queries and **raw** single-head keys. On block
   completion, left-to-right sum four raw keys and multiply by 1/4, then apply
   key RMSNorm and RoPE at the block's first position. Query heads receive their
   own RMSNorm and RoPE at the current position.
4. Score blocks with `sum_heads(relu(dot(index_query_head, block_key)))` in FP32:
   no learned head weights, no indexer `1/sqrt(d)`, no indexer softmax.
5. Incomplete cells map to the spare key `RMSNorm(raw_key_0)`, rotated at zero.
   They are **not** pooled using a partial mean. llama.cpp initializes spare
   block members to cell 0; Strata explicitly documents this dead/spare key.
6. Expand block scores to token cells. Add finite FP32 `1e9` starting at
   `floor((t+1)/4)*4`. Finite addition matters: scores can lose low bits, and the
   boost is not an unconditional infinity or a forced-tail replacement rule.
7. Select exactly `min(n_kv, index_topk + block_size - 1)` cells. Selection is
   token-level, so a budget can cut a tied block. Sort chosen IDs ascending only
   **after** deciding membership, for a stable attention reduction order.
8. Main GQA computes its own Q/K logits, scaled separately, and its own stable
   softmax over the selected causal cells. Indexer scores are not probabilities.
   Apply sigmoid gate per output lane, then final output projection.

Causality is enforced independently by exposing only cells `[0,t]` in each
sequential step; future cells do not enter either selection or main softmax.
Thus `n_kv=t+1`, not allocated cache capacity. This does not reproduce the
physical padded/circular cell layout of a llama.cpp cache. In particular, this
is not a claim of identical indexer diagnostics for batched graph construction
that has already pooled future members of the current query's block.

## Text IMRoPE equivalence (not multimodal equivalence)

CPU `ggml_mrope_cache_init` selects t/h/w by frequency sector modulo three with
bounds `sector < 3*sections[axis]`. With `(11,11,10,0)`, all 32 frequency pairs
choose one of the three text axes, never the extra axis. Every axis theta is
multiplied by the same `base**(-2/rotary_dim)` at every frequency, with no
independent-section reset in IMRoPE. If `p_t=p_h=p_w=t`, all three thetas are
equal at each frequency: `theta_j=t*base**(-2*j/rotary_dim)`.

Crucially, CPU `rotate_pairs` for `GGML_ROPE_TYPE_IMROPE` pairs lane `j` with
`j+rotary_dim/2`. “Interleaved” describes **axis assignment**, not adjacent
lane pairing. Existing `RotaryEmbeddingInference(layout='half')` is therefore
equivalent for these text positions; `layout='interleaved'` is not. Lanes after
the rotary prefix are copied unchanged. Section validation requires exact
three-axis coverage for synthetic widths too. Arbitrary multimodal positions
are intentionally not accepted.

This is mathematical equivalence, not a bitwise claim: the reusable RoPE helper
computes FP32 frequencies directly, whereas GGML advances theta by repeated FP32
multiplication. The compiled tests allow the resulting numerical discrepancy.

## Tie policies: a verified reference disagreement

**Pinned GGML CPU does not define a lower-index tie comparator.** In this
revision `ggml_top_k` creates `GGML_OP_TOP_K` directly. Its CPU implementation
uses `std::partial_sort` with comparator `data[a] > data[b]`, then swaps the
first two outputs. CPU argsort uses value-only `std::sort`, also without an
index fallback. Neither promises stable equal-score membership/order.

Strata's `topk_512` header explicitly promises lower-index ties and acknowledges
that GGML does not specify that rule. Therefore the two references cannot be
honestly called identical on all ties.

- Default `tie_policy='ggml_cpu'` emulates the inspected local **libstdc++ heap
  selection algorithm**, then sorts the selected IDs ascending. This reproduces
  the tested pinned CPU membership, not an ISO C++ guarantee across STL vendors
  or versions. Returned order intentionally differs from GGML's shuffled order.
- `tie_policy='strata'` uses lexicographic `(-score,index)` selection, then sorts
  IDs ascending. Use it when the lower-index/Strata contract is desired.

Compiled discriminator: scores `[0,0,0,0,1]`, width 4 select `[0,1,3,4]` with
the local pinned CPU function versus `[0,1,2,4]` with Strata's rule. Merely using
all-equal scores did not expose a membership difference in the original tests.
All-equal argsort at length 33 does expose non-stable ordering locally.

## State, memory and failure boundaries

Persistent FP32 buffers are preallocated once:

- keys and values: each `[max_length, n_kv_heads, head_dim]`;
- raw indexer keys: `[max_length, index_dim]`;
- completed pooled keys: `[floor(max_length/block_size)+1, index_dim]`.

Cache identities remain unchanged during steps; there is no per-token KV
concatenation or growing persistent history. Persistent cache elements total
`max_length*(2*n_kv_heads*head_dim+index_dim)` plus the pooled-key buffer.
The generic RoPE helper retains geometrically growing factors bounded by the
largest position used, which cannot exceed a state's explicit capacity during
normal use. Temporary score arrays are O(current context); selected attention
scratch is O(selection width * head width). This is a reference, not a fused or
allocation-free decode implementation. Optional diagnostics return independent
score and selected-ID copies, not an accumulating trace.

Shape, dtype, owner, chronology and capacity checks precede mutation. All six
projection callbacks, including the final output callback, validate before a
step commits its cache writes. Callback side effects, device faults, concurrent
array edits and allocation failures are not transactional guarantees. Prefill
validates the whole input shape/capacity first, but successful earlier steps
remain committed if a later callback fails.

## Reuse and validation

Reuses the existing Qwen3 attention branch's generic per-head `RMSNormInference`,
partial `RotaryEmbeddingInference`, and the established FP32 validator/sigmoid.
The dense projected-attention state's append contract does not implement QSA
selection, so selected GQA uses explicit existing-backend `xp` operations.
No additional runtime dependency is introduced. CPU selection copies scores to
the host (also under CuPy); it is intentionally not a fast GPU implementation.

Focused command, final execution:

```text
MINI_LLM_BACKEND=numpy .venv/bin/python -m pytest -q tests/test_0208_qwen4exp_attention.py
22 passed in 0.40s
```

Initial execution was `21 passed, 1 failed`: the test asserted it had exercised a
CPU/Strata membership disagreement, but its chosen vectors had not. One
localized test-only correction added the exhaustive-search discriminator above.
Production implementation was unchanged. The final exact focused command passed.

Coverage includes independent FP64 source-equation graph outputs and block
scores (including actual rotary/index dimensions), exact selected IDs, complete
and incomplete blocks, boundaries and finite tail scores, ties, width cuts,
2061-cell synthetic context with the default 2051-cell budget, prefill/chunk/step
state equivalence, reset, owner/position/capacity rejection, callback/dense
agreement, invalid callback output shapes without cache mutation, and cache
allocation identity/dtype.

The suite compiles **extracted actual pinned CPU argsort/top-k functions** with
minimal tensor/thread ABI shims, using the installed C++17 compiler/STL. It also
compiles actual `ggml_mrope_cache_init` and `rotate_pairs` with a base-RoPE-only
`rope_yarn` shim (no YaRN/scaling), and compares prefix rotations and untouched
suffixes at positions through 2057. These are operator-level extracted-source
checks, **not full linked GGML graph execution**. RoPE tolerances are
`rtol=2e-4, atol=3e-4`; FP64 branch output tolerance is
`rtol=3e-5, atol=1e-5`. Source checks skip when the pinned local checkout/compiler
is unavailable; they executed, without skips, in the reported run.

No actual GPU execution, real checkpoint attention comparison, full model logits,
quantized KV parity, arbitrary multimodal parity, or GPU tie-kernel parity has
been established. Full GGML libraries were not found in the inspected checkout;
no full GGML build was performed. This patch is standalone FP32 numerical and
state-contract validation, not decoder/model integration or bitwise parity.
