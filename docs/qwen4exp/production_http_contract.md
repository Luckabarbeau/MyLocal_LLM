# Production HTTP comparison contract — RTX 5080 GPU 0

## Acceptance boundary

Only the real production HTTP stack qualifies. Kernel/microbenchmarks, forced
four-token continuations, masked/omitted EOS, profile-trained repeats of the same
case, and two-token output agreement are **not performance acceptance**.
No optimization recommendation follows until the candidate and installed reference
have matched production pipelines and the measurements below exist.

Target device: physical GPU 0, RTX 5080,
`GPU-bea264b4-9e76-3be5-5883-7bde3fe9f82d`. Exactly one visible GPU for the server
and engine; GPU 1 is not a helper. No concurrent benchmark/test on that GPU.
Existing services/jobs must never be stopped to make room.

Targets are 2500–3000 **uncached prompt tokens per actual prefill second** and
approximately 75 **emitted tokens per active decode second**. Faster prefill is
not a failure; 2500 and 75 are the current gate floors. The requested host arena
is approximately 50 GB, not a command to pin 50 GiB. The installed arena estimate
is 46.84 GiB (about 50.30 decimal GB). Require at least 4 GiB host reserve and
record actual startup memory/arena allocation, not just a requested budget.

## Fixed workload and sampling

Use `scripts/benchmark_qwen4exp_serving.py`'s existing `sized_source` and
`source_messages`: coding-source review chat, 128 / 1024 / 4096 prompt tokens.
The default source is the standard generated Python-code workload, not an actual
repository-file corpus; `--source-file` can select read-only real files and their
hashes enter a **different** workload identity. Do not mix those corpora in one
comparison.

`run_strata_production_comparison.py` prepares these with the **installed**
Strata tokenizer and chat template, `parse_special=True`, thinking enabled. It
records tokenizer/template file SHA-256 values, exact request UTF-8 bytes and
SHA-256 per request, a canonical manifest SHA-256, source identities, sampler,
context, and user agent `qwen4exp-production-http/1`.

The frozen default manifest has 128, 1024 and 4096 sizing tokens exactly; backend
usage must confirm those counts. Request `max_tokens=256`, ordinary streaming
chat completions, `stream_options.include_usage=true`; natural EOS is respected.
Do not force the response to reach its budget. A natural response below 128
emitted tokens remains useful behavioral evidence but cannot establish sustained
decode acceptance. No token-ID output-parity requirement is imposed on stochastic
sampling, but the payload, model and tokenizer must match.

The installed config has no `sampling` block. Installed server source identifies
Qwen4exp thinking model-card defaults as `temperature=1.0`, `top_p=0.95`,
`top_k=20`. The manifest sends these explicitly. Do **not** replace them with
greedy merely to simplify comparison. If a future production config explicitly
uses greedy, both sides must use that same config and a new manifest. Shared web
settings or recovery-induced sampler changes must be disclosed from raw telemetry.

Replay the same manifest, not new prompts and not live followups generated by a
different model. Do not silently rewrite model IDs. This launcher's `--manifest`
verifies its hash and sends its saved bytes with `benchmark_request(raw_body=...)`.
The general benchmark's existing `--replay-from` is not the immutable-byte path:
it intentionally reserializes and can rewrite the model ID.

## Measurement definitions and cache separation

Per request retain exact body, metadata, raw response bytes, timestamped SSE
events, usage, finish reason, before/after snapshots and process/GPU resource
samples. Artifacts may contain private source/answers.

- Client TTFT: first nonempty content **or reasoning** delta arrival, not an empty
  role event and not total HTTP latency. Record first-content and first-reasoning
  separately. Backend first-engine-token time, if provided, remains separate.
- Prefill rate: request-local `processed_prompt_tokens / prefill_seconds`; cached
  tokens are excluded. No `prompt_tokens / TTFT` substitution.
- Decode rate: SSE/backend `usage.completion_tokens / active decode_seconds`,
  including emitted reasoning tokens as the API reports them. Never drafted,
  rejected, forward-pass or SSE-event counts. Backend-reported decode rate is
  preserved separately and may use a different numerator.
- End-to-end rate: emitted completion tokens / full request duration, separately
  labeled and never substituted for active decode throughput.
- Occupancy: report prompt, processed, reused, output, context capacity, and
  prompt+output count separately; the last is API-boundary occupancy, not proof
  of resident KV cells.
- A first submission is **not automatically uncached**. Require observed zero
  reuse for the fresh bucket. Nonzero common-prefix reuse is classified separately;
  unknown reuse is not assumed zero. Exact repeated-prefix and conversation-turn
  reuse must be measured as their own cases, with processed/reused token counts;
  they cannot replace the fresh matrix.
- Request-matched metric IDs only. Do not attribute global metric deltas to one
  request. Cache/hardware snapshots remain explicitly global observations.

## Safe bounded launcher

```sh
/home/lucka/.local/share/strata/terminal/0.1.59.1/python/bin/python3 \
  scripts/run_strata_production_comparison.py \
  --output benchmarks/strata-production-http-reference-v2 \
  --manifest benchmarks/strata-production-http-reference-v1/workload.json \
  --deadline 170 --startup-timeout 75 --max-output 256 --max-requests 3
```

The command must run from the repository root. Use a new output directory. It
checks physical GPU identity, refuses competing compute on GPU 0, preflights
46.84+4+1 GiB available host RAM, chooses a free loopback port, launches direct
`serve.server` in a dedicated process group, passes an owner-loss pipe, and tears
down **only that group**. It does not use `strata_launch_bench_capture.sh`, mutate
the saved config, change production defaults, or leave a server running. Hard
run deadline is at most 175 s plus bounded teardown; tool invocation is bounded
at 180 s. HTTP generation timeout is bounded by the remaining run deadline.
Startup and between-request reserve checks fail closed. If only two production
requests fit, retain them and mark the full matrix pending.

Exit 0 means collection ended without a transport/launch error, **not performance
acceptance**. `summary.json.production_comparison_accepted` remains false until
matched candidate evidence is reviewed. CPU mock tests validate transport/gates,
not performance.
